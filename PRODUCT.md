# Product

XDJ-RX3 Toolkit is a desktop preparation tool for DJs and operators who manage RX3 drive modifications, sample banks, logo artwork and stems on macOS and Windows.

Mode: Operate. Success means the operator understands the selected drive and output, can complete each preparation task, can see progress and recover from failure, and retains access to every existing operation.

The six navigation destinations are Modules, Samples, Logo, Stems, Install the mod and Settings. First-installation instructions are in Install the mod. USB drive selection is the initial screen. Choosing the first drive opens Modules. Loading a drive does not open a stems migration dialog. The selected playlist is prepared through the single Stems action. Drive inspection remains accessible from the USB drive control at the bottom of the sidebar. The local vanilla-JavaScript page runs inside pywebview without a build step or a network dependency. Python is the authority for capabilities, limits, dependencies, validation and long-running work. Jobs are polled. The Install the mod screen recaps every checked module, logo, sample bank and stem preparation destinations. Module installation starts there: destination, first-use acquisition with explicit legal consent when needed, then an explicit installation confirmation. No right-hand Modules setup panel or acquisition prompt at startup.

The UI is bilingual EN/FR. French uses professional vouvoiement and the project glossary. Hardware labels and legal meaning are preserved. Preview UI must not add disclaimers about schematic rendering, screenshots or illustrative content. Keep only instructions and limitations that affect the user's actions. Routine loading and preview refreshes must not insert status banners or shift the layout; retain actionable errors and progress for long-running jobs.

Product behavior, audio behavior, bridge arguments/results and service implementation are outside the UI redesign. Minimum window is 880x560; default is 1180x820. Approval is required before implementation, dependency changes, feature removal, out-of-scope writes or commits.

Choosing artwork activates Logo through the normal module-selection rules. Stems always targets the selected USB drive and includes waveforms. Hardware tutorials live with their individual modules; the Logo canvas remains an editing control. For prepared waveforms, Stem Preview starts after the first two-second binary audio block from a token-scoped loopback endpoint. Remaining blocks load ahead; an uncached seek requests its block with priority. Playback and role gains share one Web Audio clock, without per-toggle bridge requests. Legacy files without prepared waveforms retain the existing analysis fallback. This preview change is explicitly authorized by the live-interaction UX request; the separator and player audio implementations are unchanged.

Authorized player navigation: SAMPLES replaces the STATUS touchscreen tab when Samples is enabled. Tapping the active KEY, STEMS, SAMPLES or BEAT FX tab closes it to STATUS; another tab switches directly. Pressing HOT CUE, BEAT LOOP, SLIP LOOP or BEAT JUMP also closes the selected touchscreen panel, clears its tab selection and restores native touch handling before dispatching the chosen pad mode. Release events and unrelated keys do not close panels. Panel navigation preserves playing samples and stem settings; held samples still receive their release. Samples no longer extends the SLIP LOOP cycle. Tutorials start in HOT CUE and animate automatically, with pause and reduced-motion support.

The Stems screen has one preparation flow and no external stem import. Opening music from USB uses the globally selected drive; without one it opens the USB screen. Preparation always targets vocals, drums and instrumental using the quick preset for new calculations. There are no quality or stem-count selectors. The same playlist job keeps complete valid packages regardless of their old preset, adds only missing drums to existing vocals, converts legacy formats and completes waveforms. v0.5.2 PCM is copied unchanged, originals are backed up, and waveform analysis runs without re-separating existing stems. Preview uses interactive-latency Web Audio and a bounded local worker to precompute signed mixes for all stem selections, displayed as 3Band, Blue or RGB.

Waveforms are prepared together in Blue, RGB and 3Band for every audible stem combination. The accelerated engine streams PCM once and filters in memory, with a bounded-memory fallback. No waveform choice or My Settings confirmation is required. Older single-format packages can be completed from Stems without separating or re-encoding audio; unavailable sources are skipped. See the [waveform formats](REFERENCES.md#doc-waveform-formats).

Authorized stem gain preservation: separator outputs retain their amplitude in temporary float WAVs. New PCM format 3 stores 16-bit samples plus a validated per-role playback scale; preview, waveform reconstruction and RX3 mixing restore that scale. Old format 2 remains readable. New files require the updated mod, and processing cache identities invalidate normalized older outputs.

Authorized Samples workflow: local projects continuously save all banks, settings and source-audio copies on this computer, independently for each selected drive path. Creating, renaming, deleting or selecting an active bank never writes USB immediately. Save to USB drive exports the project explicitly; failures retain its unsent state. The screen and Samples navigation mark local-only changes. Bank switches preserve edits without a discard prompt. The advanced technical module group is omitted from Modules; dependency resolution remains unchanged.

Running tasks remain indicated in the sidebar even when progress is hidden. Closing the application during a task asks for confirmation before cancellation and waits for worker cleanup; declining preserves the task and preview. The Samples drive chooser routes to the shared USB screen. Tutorials describe restoring the display for the currently selected pad mode instead of returning to STATUS.

Waveform completion is part of Prepare stems for the selected playlist. There is no separate completion prompt or button. Existing packages are verified against their embedded source hash and checksums, even without an outer manifest. Complete packages need no recalculation. Corrupt packages are reported without overwriting them; changed sources require fresh preparation.

Waveform acceleration uses an optional standalone NumPy worker in the already installed separation runtime. It batches two combinations and filters at most two concurrently, falling back to serial multi-format filtering when scratch space is insufficient, preserving PCM gain, rounding and cancellation ownership. Blue/RGB/3Band output retains the reference representation; missing runtime retains the scalar fallback. No dependency is installed automatically.
